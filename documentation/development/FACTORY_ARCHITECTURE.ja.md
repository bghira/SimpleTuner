# データバックエンドファクトリの構成

## データセットの構築

ファクトリは識別子を検証し、生成データセットを展開して、メタデータの依存元を先に処理します。ビルダーはソースとメタデータのプロバイダーを開きます。`DatasetRuntime` はプロバイダー、解決済み設定、関連データセット、アーティファクトキャッシュを結び付けます。`StateTracker` はハンドルを登録し、従来の呼び出し元向けの登録も保持します。

```text
FactoryRegistry → builders → DatasetRuntime
                              ├─ BaseDataBackend
                              ├─ MetadataBackend
                              ├─ TextEmbeddingCache / VAECache
                              └─ training dataloader
```

## プロバイダーの契約

ソースプロバイダーはファイルやオブジェクトを読みます。メタデータプロバイダーは採用済みサンプルとクロップの幾何情報を公開します。`describe()` は利用可能な件数とリビジョンを返し、`read_page()` は件数を限定したページを返します。`read_samples()` は指定フィールドを参照順に読み、重複を保持します。参照はプロバイダーの識別方式に従います。

前処理には `iter_preparation_batches()` と `iter_preparation_text_records()` を使います。プロバイダーによる作業分割は、学習時の反復やパディングから独立しています。アーティファクトはソースと別のストアに置けます。オンラインのテキストエンコードは現在のバッチに対して行います。

ローカル探索、AWS、CSV は従来のメタデータとスケジュールを共有します。Hugging Face は準備済み変換を Arrow シャードで分割できます。Webshart のネイティブ Parquet は、索引付きの採用済みビュー、対応するクロップのシャード単位の変換、再構築できるエポックカーソルを使用します。

## 学習と再開

トレーナーはランタイムに予定バッチを要求します。ミキサーがデータセットを選び、フェッチャーが先読みできます。トレーナーはバッチ消費後に進行位置を確定します。チェックポイントは消費済みの位置とミキサー状態を保存します。ネイティブ再開には同じ採用済みビュー、サンプリング設定、分散レイアウトが必要です。

## 検証

新しいプロバイダーは、参照の安定性、指定フィールドと読み取り順、前処理の網羅性、中止と再オープンの動作をランタイム経由で検証します。ネイティブスケジュールではカーソルの再現を検証します。古いビューの読み取り中に新しいビューを公開するケースも含めます。新しいアーティファクトについては前処理と学習のキーが一致することを確認します。

```bash
.venv/bin/python -m unittest -v -f tests.test_dataset_runtime tests.test_webshart_parquet_backend tests.test_vae_cache_traversal
```
